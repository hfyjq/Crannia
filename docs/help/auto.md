## 关于自动模式

针对长流程任务或步骤繁杂的场景，crannia 提供自动模式来改善您的使用体验。自动模式由两层组成：边界限位闸与自动审查。边界限位闸在自动审查之前先行拦截所有触犯硬性边界的行为；通过限位闸的行为会继续移交自动审查判断。若自动审查判定某个动作为安全，该动作即被放行；反之则被驳回。

==请注意：即使在自动模式下，您仍然是生产环境安全的第一责任人。==

## 两层机制

- **边界限位闸**（下称「限位闸」）：命中限位闸的行为会遭到确定性拒绝或被提升为向您询问。确定性拒绝例如出网类命令（curl、wget、ssh、scp、nc、rsync 一族）；命令里提到受保护路径时，会提升为向您询问。
- **自动审查**：由审查模型对行为请求进行审查。若审查模型认为某个动作具有破坏性、有害或不可逆，它会拦截该动作。自动审查的判断并非一成不变：若您在与 crannia 对话时明确声明了某些边界或要求，这些语句也会成为自动审查的参照条目。需要注意的是，这些条目并不具备绝对约束力，因为它们只存在于对话里；若希望它们获得保证，请把相应条目写入「设置 · 安全设置 → 自动审查配置」。

## 判定顺序

1. 限位闸：命中即拒绝，或被提升为向您询问。
2. 您本次或本会话中已批准过同一件事：放行。
3. 写操作、可逆，且目标均在工作区内：放行。
4. 只读工具：放行。
5. 以上均未命中：移交自动审查。

## 自动模式的其他边界

- **熔断**：连续 {breaker_consecutive} 次或累计 {breaker_total} 次被自动审查拦下时，下一次行动会强制向您发起询问，并将计数清零。本轮对话不会因此中断。
- **无响应**：自动模式下，审批等待默认为 {approval_timeout_seconds} 秒，该数值可在设置页自行修改。倒计时结束仍无响应时，模型会收到「无可用通道」的回执并继续工作，这种情况不会被视为一次拒绝。
- **无从判断**：存在某些时候，自动审查可能会无从判断行为的安危，此类情况一律按危险动作处置，但不计入熔断次数。
- **并非绝对安全**：自动审查也并非绝对安全，它无法判断行为结果是否真实，请关注生产环境安全。
- **网络连接**：部分情况下的网络连接行为会被阻拦，此情况不计入熔断次数。
- **全部放行**：需要注意的是，「全部放行」选项并不会移除限位闸。
- **需要显式同意的行为**：跨区搜索、删除、写工作区之外、逐应用授权。这些行为仍会弹窗询问。
- **不可逆的操作**：仍会发起询问。例如数量庞大的批量删除，不会仅因自动审查认为「安全」就直接执行。

## 相关设置

- **默认模式**（设置 · 对话）：决定新建对话使用哪一档权限。它只影响新开的对话；当前对话仍需通过输入框上的按钮修改。
- **审批等待**（设置 · 对话）：决定自动模式下询问的挂起时长；数值为 0 时表示持续等待，直到您作出答复。
- **访问与命令名单**（设置 · 安全）：在此配置批准的域名与命令。
- **自动审查配置**（设置 · 安全）：写下希望自动审查长期遵守的条目，可以逐条增删、修改。
- **关闭安全询问**（设置 · 操作）：降低危险行为的审查级别，即把「必须询问」的问题降级为「可以记住」。首次执行仍会询问。
