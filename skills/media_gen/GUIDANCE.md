# 生图的领域纪律

**权威在哪**：你正在对接的是某一家生图服务的**厂商 API**，不是"画图"这件抽象的事。
每个参数的合法值、每个模型支持什么，以**那家的官方文档**为准 ——
同一条请求参数打不同模型会撞 400（有的模型不接受 `sequential_image_generation`）。

你要伸手拿的东西：

- **配置**：`data/media_gen_credentials.json`（条目名 · base_url · model · api_key）。
  拿不准地址填到哪一层，去看那家文档里 curl 示例的完整 URL，**照着它的层级填**。
- **模型清单**：能用 API 列就别手抄（火山 `GET /api/v3/models` 给 id 与状态）。
  模型名与显示名常常不是同一个串。

三条判断：

1. **提示词是给模型的，不是给用户的**：把画面要素写全（主体 · 动作 · 场景 · 风格 · 构图），
   别只丢一个名词。
2. **一次一张**：要几张就调几次；不要假设服务支持一次多图。
3. **失败先看状态码再改提示词**：401/404/429 都不是提示词的问题，改提示词只会白花钱。
