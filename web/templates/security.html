    🧊 ICE

    本地安全模块 —— 全部在这台机器上跑，不外接任何外面的名单。
    开着的时候，agent 从文件 / 表格 / 邮件 / 网页里读进来的身份证、银行卡 不会原样送出去：它拿到的是占位符，只有在你自己的机器上才换回真值。
    ★ 你在对话里自己打的那些不换 —— 那是你已经决定交出去的， 而且不换才能让「帮我算算这个号」这类活儿照常能用。

    ICE 增强防护（总开关）
    关掉它，下面所有防护一起停。
    信息层（保护隐私）
    文件 / 表格 / 邮件 / 网页里读进来的身份证、银行卡。
    只有这条路 —— 认得出（校验位）才换，认不准的一律只报不改。
    网络层（金丝雀）
    埋了一个诱饵值：只要它出现在要发出去的东西里 （网页抓取 / 链接解析 / 邮件收件人与正文），就阻断并报警。
    诱饵串：…
    把它抄进一份你不想它外流的文件里 —— 那份内容一试图出站，这条闸就会响。 是检测，不是预防；也只护这一个值。

    有人在要求您吗？

    有人暗示或要求您关闭 ICE 吗，这很有可能是诈骗行为！

    ⚠ 如果您正在通话，请立即挂断！ 来电者可能在冒充他人！
    ⚠ 请勿付款或分享您的信息

    ⚠ 请注意信息安全

    诈骗者通常会提供未知插件或未经验证的功能，借此窃取您的个人信息或其它数据。
    来自可靠机构的工作人员绝不会要求您关闭此设置！

    🌐 网络策略

    控制框架联网访问哪些目标。名单之外的域名，第一次访问时会问你一次。
    三处来源共用同一份名单：对话里批准、「全部放行」、以及你自己在这里加的。

    全部放行（不再询问新的域名）
    打开后，任何公网域名都不再询问，直接访问。
    它只是名单里的一行「全部」—— 关掉它就等于把那一行删掉，不会另外记一个开关。
    访问白名单

      ⚙ 操作设置

      控制框架执行命令（bash）时要问哪些、记住哪些。

      全部放行（不再询问新的命令）
      打开后，任何命令都不再询问，直接执行。
      ⚠️ 这一条不影响下面那个危险档开关，也不影响出网类命令（curl/wget/ssh 一族是硬拒，不问）。
      执行白名单
        要逐字写整条命令（判定用的是原文，不是前缀）。
        关闭安全询问（危险命令降级）
        默认情况下，碰到框架自己的源码/数据、密钥、仓库配置（core/ data/ .env .git CLAUDE.md 一族） 以及 git 命令，每次都问、且不允许「本次对话内不再询问」。
        打开这个开关后，它们降级成普通命令 —— 仍然会问第一次， 只是批准之后可以记住。
        它不会变成「不问」：一次点击不该等于永久放行一整类危险操作。 「出网类命令」（curl/wget/ssh/scp）是硬拒，这个开关也管不着。
        只读命令免问（WB3）
        打开之后，看一眼的那类命令（ls cat head grep pwd wc stat 等 20 个）不再弹窗，直接执行。
        它只放宽"看"，不放宽"改"：命令里一旦出现重定向（>）、 管道（|）、串起来（&& ;） 或取变量（$），整条照旧问 —— 所以 cat a b > c 会问，而 cat a b 不问。
        危险档一个字不受影响：git、提到框架源码/密钥的命令、 大批删除，每次照旧问；出网类仍然硬拒。
        默认关。打开之后每命中一次，运行日志里会留一行。
        批量删除的强制确认（一次超过 N 个必问）
        一次删除超过这个个数时，两个模式都会被拦下来问你 —— 自动模式也一样（自动审查器越不过它）。
        那一次浮窗只给「同意 / 不同意」，不给「本次会话内不再询问」 —— 给了的话，你点一次这个闸就把自己关了。
        填 0 = 关闭这个闸（回到"交给分类器 / 会话授权"）。出厂 30。
        ⚠️ 自动模式下超限会挂起等你 —— 你不在，这一轮就停在这儿， 回来才继续。这就是这个闸的代价，也是它可以关掉的原因。

        🎚 投入档

        一次任务值多少投入。档位管的是能力与代价，不管界面偏好 —— 今天随档变的只有两根：子 agent 个数与思考模式。
        档名与档数只在 core/tiers.py 定义一处，这一页只是把它画出来 （改档表这里会自动跟着变）。

        当前：—
        ⚠️ 改档是一次冷启动 —— 它进提示缓存键，所以正在进行的那段对话不受影响， 下一段（或 /clear 之后）才用新档。
        想在这一段里立刻生效，在对话里打 /effort <档名>： 它会当场重算一次缓存前缀，并把这件事说给你听。

        🧭 交互模式

        这一段怎么干活。模式管的是行为，与上面的投入档正交 （那是能力与代价，这是"写的东西要不要先问"）。
        模式表只在 core/modes.py 定义一处，这一页只是把它画出来。

        当前：—
        ⚠️ 改模式是一次冷启动 —— 它进提示缓存键，所以正在进行的那段对话不受影响。
        想在这一段里立刻生效，在对话里打 /mode <名字>。
        ★ /clear 不会动它 —— 「我要重新想一遍」和「我退出计划模式」 是两件事，别把它们挤成一个动作。
        审批超时（秒）—— 只对「自动」档
        自动档下弹出审批窗时，等这么久就按 「没有可问的通道」结算（不是判你拒绝 —— 模型会换一条不需要批准的路，或者写进回复告诉你）。
        ★ 治的是「用户离开了你却老是断掉」。0 = 关（一直等）。
        ⚠️ 只挂自动档：手动档下你本来就在，自动拒会把你正要批的那件也毙掉。
        ⚠️ 改设置是一次冷启动；已经挂着的那一个倒计时按改之前的数走。

        💬 对话显示

        控制回复怎么出现。这一条只影响观感 —— 不改变模型说什么、也不影响工具调用。

        逐字输出（流式）
        打开后，回复边生成边显示（虚线框是预览，定稿后会被正式气泡替换）。
        默认关：逐字输出的口碑五五开 —— 有人要"看得见在干活"， 也有人嫌闪烁分心。⇒ 做成开关，不替你决定。
        ⚠️ 关掉它回复一样完整，只是等齐了才出现。

        🎛 框架模式预设

        一次把三处调成一套搭配：投入档 + 记忆接续 + 后台抽取频率。
        ⚠️ 它不是第四个设置 —— 覆盖的就是下面那三处本身； 改任一项就回到「自定义」，而且调回同值也算改过。

        当前：—

        记忆接续

        控制每次重启 Agent 时注入多少历史对话上下文。
        重启后新对话开始前，系统会从 SQLite 加载最近的对话记录注入给模型。

        🔄 更新 极少量历史（0-4轮）
        ⚖️ 平衡 适度注入历史（默认）
        🧠 记忆 最大化历史注入

        🧠 长期记忆

        Agent 把值得跨会话记住的事实写进记忆库（`data/memory/facts/`），新会话自动带上索引。
        写记忆有两条路：主 Agent 在对话里自己写；以及每 N 个合格轮，后台补跑一次「记忆抽取」查漏。

        启用「写记忆」
        默认开。它同时是两条写路的总闸：主 Agent 在对话里自己 memory_write， 以及后台每 N 个合格轮的「记忆抽取」。
        ⚠️ 关掉后读记忆不受影响（索引照挂、memory_read/search 照用）； 工具表也照发 —— 只是执行侧会拒（K5：摘表会断缓存前缀）。
        启用「记忆巩固」
        默认开。后台的通读 + 合并 + 精简：把日报/会话笔记里的新信号沉淀进已有条目， 相对日期转绝对、改写被推翻的事实。
        ⚠️ 门控很严 —— 距上次整理 ≥24 小时 且期间碰过 ≥5 个会话 才跑一次 （两个都开才生效；写记忆关了它也没意义）。运行时会占一个并发名额。
        后台抽取频率（每 N 个合格轮）
        默认 3。设 1 = 每轮都抽取（更频繁、更贵）；调大 = 更省、记得更晚。
        ⚠️ 主 Agent 当轮已自己写过记忆时，那一轮会跳过（不重复抽取）。

        🧠 记忆库

        Agent 记住的跨会话事实（存在 data/memory/facts/）。 开关是全有或全无，而记忆真正的问题是「这一条记错了」 —— 所以这一页让你 自己看、自己改、自己删。

        全部条目
        点「编辑」改这一条；点「删除」把它移出记忆库。 ⚠️ 删除会把这条记进封条账本（tombstone）—— 之后 Agent 抽取/整理时 不许把它重新生成（删除是你的动作，不是它的）。
        编辑条目
        已删除（封条账本）
        这些名字不许再被生成。误删了就点「解除封条」—— 但内容不会回来 （内容在删除那一刻就没了），恢复内容要重新写一条。

        清空记忆库？

        会把 全部 条记忆删掉，并给它们全部落上封条 —— 之后 Agent 抽取 / 整理时不许把它们重新生成。

        ⚠ 内容不会保留 —— 删掉就没了，封条只保证"它不会自己回来"。
        ⚠ 想留后路：先逐条看一眼，或者事后在下面的封条账本里点「解除封条」 （那只是允许重新写，内容仍要重新写）。

        🪟 上下文滑窗

        长会话的压力兜底：消息数超过上限（`max_history`）时，把最早的消息移出上下文， 保留摘要头与最近的轮。被移走的消息仍在历史库里，Agent 可用 history_search 找回。

        启用上下文滑窗
        默认开。只在"对话冷下来"时才剪 —— 上次活动距今 ≥ 闸值（见下）才会触发； 正在连续对话时不剪（保护提示缓存，省 token）。
        ⚠️ 关闭后长会话不再丢弃消息 —— 上下文压力全交给自动压缩处理。
        冷闸时长（分钟）
        距上次对话活动超过这个时长的"回归"才允许裁剪。默认 90。

        ⏪ 回退（/rewind）

        /rewind <轮号> 回到某一轮之前（旧的不会删，/resume 能回来）。

        回退时把工作区文件也退回去
        默认开。对话和文件一起退——办公场景里「改错了一个文档，回到上一步」 本来就该是两件事一起。
        ⚠️ 关掉的话只退对话，文件保持现在的样子（回退回执里会写明）。
        ⚠️ 如果你自己在编辑器里改过某个文件，它不会被覆盖 —— 那一批一个文件都不写，回执里会逐条说明。

        对话回顾

        离开一段时间后回来时，先说一句「我们到哪了」。零模型调用 —— 它读的是会话笔记（Current Status / Next Steps / Open Questions），不额外花钱。

        启用对话回顾
        关闭后回来不再出现那一段（默认关）
        回顾触发时间（分钟）
        距上次活动超过这个时长才算「离开」。默认 30。
