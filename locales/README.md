# locales/ —— 界面文案的语言包

> *中文原文就是键；一种语言 = 一个 JSON 包。*

## 目录长什么样

```
locales/
  README.md        本文件
  en.json           运行时包：{ "中文原文": "English" }
  glossary.csv      术语表（一处定义，所有译文都应当对齐它）
```

需要添加更多语言时，只需在同目录下增加一个 `xxx.json`，形状同 `en.json` 一样。

## 添加一门语言含有四步

1. `core/i18n.LANGS` 增加一个语言代码 —— 这是唯一需要动代码的地方（一个元组）。
2. 照 `en.json` 的形状新建 `<代码>.json`：键是中文原文，值是译文。
3. 全量填入新的语言，或只填一部分 —— 没填的键会自动回落显示中文。
4. 设置页「界面语言」的下拉从 `locales/*.json` **自动发现**，多一个文件便多一个选项。

## 硬性规则

1. **中文原文 = 键。** 改原文等于换了一个键，这会导致旧译文变成孤立文件，因此翻译工作应当在源文案定稿之后再进行
2. **缺失译文时回落中文，不显示裸键。** 界面上不应当出现
   `settings.memory.viewer.disabled` 这种键名。

占位符（`%s` / `{name}`）**原样保留**，数量与名字需要确认能够匹配

## 风格约定

- 活动横幅上的「正在干什么」（`loadingPhrases.js`）的译文应当是**单个单词**，而非短语。
  例如：`思考中` → `Thinking`（不是 `Thinking it over`）· `整理中` → `Tidying`（不是 `Tidying up`）。
  省略号会由界面自行加入（`StatusBar.jsx` 渲染 `{phrase}…`），译文里不应当重复书写 `…`。
- 按钮文案按中文字数已预留位置，英文超过约 1.8 倍时会导致被截断，因此所有的长句都应当尝试精简

## 无需翻译的内容

工具 `description` / 参数 schema · 工具回执（仅模型可见）· 日志 `print()` · 系统提示词 ·
审批载荷与协议字段 · 命令**名**（`/clear` `/effort` 保持英文；命令的**回话**需要翻译）·
skill 自己的描述 · 用户消息与助手回答。

## 与「回答语言」的边界

- **界面语言**（本目录）＝ 按钮 / 标签 / 通知 / 命令回话。
- **回答语言**（`core/response_language.py`）＝ 模型写什么语言。

两者各有一个设置项；互不影响。

## `en.json` 是怎么来的

由开发流程生成，通过手动更改 `en.json` 也可以生效，但在下次生成会以流程里的那份为准。
