# locales/ —— 界面文案的语言包

> 一句话：**中文原文就是键**；一种语言 = 一个 JSON 包。

## 目录长什么样

```
locales/
  README.md        ← 本文件
  en.json          ← 运行时包：{ "中文原文": "English" }
  glossary.csv     ← 术语表（一处定义，所有译文对齐它）
```

以后加日语 / 繁体，就是同目录下多一个 `ja.json` / `zh-tw.json`，形状与 `en.json` 一样。

## 加一门语言 = 四步，界面代码一个字节都不用改

1. `core/i18n.LANGS` 加一个语言代码 —— 这是**唯一**需要动代码的地方（一个元组）。
2. 照 `en.json` 的形状新建 `<代码>.json`：键是中文原文，值是译文。
3. 填。可以只填一部分 —— 没填的键回落显示中文。
4. 设置页「界面语言」的下拉从 `locales/*.json` **自动发现**，多一个文件就多一个选项。

## 两条硬规矩

1. **中文原文 = 键。** 改原文等于换了一个键，旧译文就孤了 —— 所以源文案定稿之后再翻。
2. **缺译文回落中文，永不显示裸键。** 界面上不许出现
   `settings.memory.viewer.disabled` 这种键名。

占位符（`%s` / `{name}`）**原样保留**，数量与名字都要对得上。

## 风格约定

- 横幅上那句「正在干什么」（`loadingPhrases.js`）的译文一律是**单个单词**，不要短语。
  例：`思考中` → `Thinking`（不是 `Thinking it over`）· `整理中` → `Tidying`（不是 `Tidying up`）。
  省略号由界面自己加（`StatusBar.jsx` 渲染 `{phrase}…`），译文里别再写 `…`。
  理由：横幅每隔几秒换一个词，短语读起来像一句话、还容易被截断；单词是状态标签，不是叙述。
- 按钮文案按中文字数留了位置，英文超过约 1.8 倍会被截断 —— 长句子改写短，不要靠缩字号。

## 不翻的东西

工具 `description` / 参数 schema · 工具回执（给模型看）· 日志 `print()` · 系统提示词 ·
审批载荷与协议字段 · 命令**名**（`/clear` `/effort` 保持英文；命令的**回话**要翻）·
skill 自己的描述 · 用户消息与助手回答。

## 与「回答语言」的边界

- **界面语言**（本目录）＝ 按钮 / 标签 / 通知 / 命令回话。
- **回答语言**（`core/response_language.py`）＝ 模型写什么语言。

两者故意分开，各有一个设置项；互不影响。

## `en.json` 是怎么来的

由开发流程生成，生成工具与中间表不随发布出去 —— 发布物里就是这一份成品。
手工改 `en.json` 也能生效，但下次生成会以流程里的那份为准。
